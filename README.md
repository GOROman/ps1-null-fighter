# NULL FIGHTER

![NULL FIGHTER](docs/screenshot.png)

初代 PlayStation 向けのキャラクタービューア兼ミニゲーム。PSn00bSDK で書かれていて、60fps で動きます。

**このリポジトリのコードとツールは、すべて Claude Code（Claude Fable 5.1）だけで書かれています。人間は 1 文字もコードを書いていません。** 人間がやったのは日本語で要望を出すこと、画面を見て感想を返すこと、素材を渡すことだけです。

素材も生成 AI 製です。キャラクターのデザイン画は ChatGPT、そこからのモデル・テクスチャ・（金髪キャラの）リグとアニメーションは Tripo3D で作りました。

- Tripo3D の FBX キャラクター（スキニング＋アニメ付き）を PS1 用のリジッドスキンモデルに変換して表示
- ボーンのない静的メッシュ（Tripo3D 生成の制服キャラ）を自動セグメント化してリグとアニメを合成
- 猿がスカートの格子を歩き、囲った区画の布が落ちる Dancing Eyes 風のミニゲーム
- バーチャファイター風の CPU 対戦格闘モード（起動時のモード）。32 種の技、コンボ、戦略 AI、自動カメラ

## 動かし方

ビルドには PSn00bSDK のツールチェーンと、`python3` + `numpy` + `Pillow` + `xatlas` が必要です。

```sh
pip install numpy pillow xatlas
cmake --preset default .      # PSN00BSDK_LIBS が設定されていること
cmake --build ./build         # build/nullfighter.cue ができる
```

このリポジトリでは `build.sh` がリモートのビルドマシン（`BUILD_HOST`、既定 `mac-studio.local`）に rsync してビルドし、CD イメージ（`build/nullfighter.cue`）を `build/` に持ち帰ります。

```sh
./build.sh
```

## 操作

起動するとタイトル画面（背景で CPU 同士のデモ対戦）。十字キー上下でモードを選び、START で開始。

| モード | 内容 |
|---|---|
| 1P MODE | パッド 1 の P1 vs CPU |
| VS MODE | パッド 1 の P1 vs パッド 2 の P2 |
| CPU MODE | CPU 同士（観戦） |

格闘モードの操作はバーチャファイター方式の P / K / G。

| 操作 | 動作 |
|---|---|
| 十字キー 左右 | 前進 / 後退 |
| △ (P) | パンチ：ジャブ / 前+P ストレート / 後+P フック / 下+P アッパー |
| ○ (K) | キック：ハイキック / 前+K 回し蹴り / 後+K 後ろ蹴り / 下+K 足払い |
| P + K | 必殺技：スピニングバードキック / 前 ドラゴンキック / 後 ハリケーン / 下 スライディング |
| □ (G) 押しっぱなし | ガード |
| 攻撃中に P / K | 次の技につなぐ（最大 4 連） |
| START + SELECT | タイトルへ戻る |

1P / VS の試合（2 本先取、最大 3 ラウンド）が終わるとタイトルに戻ります。タイトルで START + SELECT を押すとモデルビューアに入ります。

### ビューア

| 操作 | 動作 |
|---|---|
| 十字キー | 猿の進行方向（分岐で選択、入力がなければ乱数） |
| 左スティック | カメラ回転 |
| 右スティック 上下 | カメラ上下 |
| SELECT + 十字キー | カメラ回転（デジタルパッド用） |
| SELECT + △ / × | カメラ上下 |
| SELECT + □ | 布をリセット |
| △ / × | ドリー（距離） |
| □ / ○ | 画角ズーム |
| L1 | モデル回転 |
| R1 / START+SELECT | IK モード ON/OFF（入ると腰のダンスが始まる） |
| L2 / R2 | アニメ切替（IK モード外） |
| START 単押し | キャラ切替（制服 / 金髪 / 3 人目） |
| START + SELECT | タイトルへ戻る |
| L3 | アニメ一時停止 |

格闘モードは金髪 vs 制服の 3 人目。ライフゲージ・タイマー・ROUND/FIGHT!/K.O. 表示、ヒットストップと画面揺れ、当たった手足の位置にヒットエフェクト、使った技名の表示があります。画面左のバーはフレームプロファイラ（H-blank 単位、白線が 1 フレーム、1 フレームを超えた分は 2 列目へ）。黄=入力、橙=ポーズ/IK、緑=頂点変換、シアン=プリミティブ、マゼンタ=オーバーレイ、赤=GPU 待ち、黒=VSync 待ち。黄色の横線は直近 0.5 秒のピーク。

## 構成

```
src/
  main.c      メインループ、入力、床（市松）、プロファイラ、HUD
  render.c    リジッドスキンレンダラ（ボーンごとに GTE で変換、Gouraud/Flat）
  anim.c      クォータニオン補間のポーズ評価、ローカル行列と FK 再計算
  ik.c        2 ボーン IK（余弦定理）、頭のカメラ LookAt（制限＋遅れ追従）
  walker.c    布ゲーム：猿のランダム/操作ウォーク、囲い判定、落下する布片
  fight.c     格闘モード：技テーブル駆動の攻撃、幾何学的な当たり判定、コンボ、戦略 AI、自動カメラ、HUD
  title.c     タイトル画面：ロゴとモード選択メニュー（1P / VS / CPU）
  moves_table.h  tools/moves.py が生成する 32 技のパラメータ表
  camera.c    軌道カメラ
  model.h     model.bin のフォーマット
tools/
  fbx2ps1.py  FBX → model.bin / .tim 変換（メインパイプライン）
  fbxparse.py FBX バイナリの最小パーサ
  meshopt.py  QEM デシメーション、xatlas 再展開、ベイク、隠面除去、関節カット
  autorig.py  静的メッシュのセグメント化、合成スケルトン、手続きアニメ
  bodygen.py  胴・腕・脚を断面計測のレイズで再生成し元テクスチャを投影ベイク
  sprite.py   猿スプライト（4bpp TIM）とタータン柄の生成
  moves.py    32 技の定義（既存クリップの流用 + キーフレームから手続き生成）と moves_table.h の出力
assets/src/   元の FBX とテクスチャ（Tripo3D 生成、デザイン画は ChatGPT）
```

## アセットパイプライン

CMake が `tools/fbx2ps1.py` を呼び、両キャラを `build/assets/` に変換します。

金髪キャラ（`character.fbx`）は Tripo3D でリグとアニメーションまで付けた FBX をそのまま変換します。頂点はいちばん重みの大きいボーンのローカル空間に置き、アニメは 15fps でクォータニオンにサンプルします。

制服キャラ（`schoolgirl.fbx`）はボーンもアニメもない Tripo3D 生成メッシュなので、以下を順に行います。

1. 隠面除去（服の下の素体など、2cm 以内に同じ向きの面がある三角形を削除）
2. 元のスカートを計測して削除し、楕円コーンのプリーツスカートを生成（専用のタータンテクスチャ）
3. 関節の高さで平面カットし、ボーンごとに独立したシェルへ分割
4. 胴・腕・脚をレイズで再生成し、元テクスチャを最近傍三角形経由で投影ベイク（`--gen-body`）。頭・髪・顔・手は元メッシュ
5. QEM で三角形数を削減（顔の目・口まわりは固定）
6. xatlas で UV を再展開してベイク。顔は 2 枚目のテクスチャ、髪は本体アトラスの一角
7. 幾何ルールで 11 パーツに分け、二足歩行スケルトンと手続きアニメ（idle/walk/run/wave/punch）を生成
8. IK チェーン（腕・脚・頭・腰）とスカートの四角形グリッドを model.bin に書き出し

主なオプションは `CMakeLists.txt` の `convert_model(...)` にまとまっています。`MODEL_TRIS` で三角形の目標数を変えられます。

## 格闘モード

技は `tools/moves.py` に 32 個定義されています（パンチ 8、キック 12、必殺技 12）。Tripo3D のクリップを使う技（ジャブ、前蹴りなど）と、部位ごとの角度キーフレームからスケルトン上に生成する技（回し蹴り、アッパー、足払い、旋風脚、宙返り、スピニングバードキック…）があり、どちらもダメージ・ノックバック・ヒットストップ・再生速度・有効フレーム・必要な打点の高さ・前進量・多段ヒット間隔・ダウン/浮かせのパラメータを持ちます。同じ表が `src/moves_table.h` としてランタイムに渡り、当たり判定は「打撃部位（手・足・膝/頭）が相手の軸の手前 450 から奥 1300 まで、横ずれ 520 以内」を実際のポーズから毎フレーム判定します。攻撃中は打撃部位が相手の軸を通るように体の向きを補正します。

AI は相手の攻撃の出がかり／硬直、のけぞり、距離帯、体力差、残り時間からアクションを選び、P1 は攻め、P2 は待ちの性格です。近距離ではコンボ（ジャブ→ジャブ→膝→ハイキックなど 12 種）、中距離では射程に合うキック、劣勢時は後退してから必殺技を出します。

相手の出がかりにはガード（立ちガードは中・上段を削りダメージに抑え、下段技とダウン技は抜ける）、攻撃中の相手に当てればカウンターヒット（1.5 倍、COUNTER! 表示）、連続ヒット数表示、ステージ端（±4200）へ吹き飛ばせばリングアウト、無傷で勝てば PERFECT 表示があります。ガードされた側は下段技で崩しにいきます。

## ランタイムの要点

- 頂点はボーンローカル、ボーンごとに `view * bone` を GTE にロードして RTPT。ライト行列は回転行列より先に作る（`MulMatrix0` が GTE の回転行列を上書きするため）
- プリミティブ組み立ては SDK の `memory` clobber 付きマクロを避け、32bit ワード書き込み
- 2 ボーン IK はワールド行列上で「ベクトル a を b へ向ける最小回転」だけで解くので、任意のボーン軸で動く
- 布ゲームは model.bin の辺と四角形（`ModelQuad`）を使い、歩いた辺で分断された小さい側の区画を切り取って `Renderer.cut` で非表示にする
